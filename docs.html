01 What ConvOps Monitors

ConvOps connects to your AWS account via a read-only IAM role and monitors CloudWatch Alarms in real time — across CPU, memory, error rate, latency, and any custom metric you've configured.

Alarm Types
CPU Utilization

Threshold alarms on EC2, ECS tasks, RDS, Lambda concurrency.

Memory Usage

Container-level and instance-level memory alarms.

Error Rate

5xx rates, Lambda errors, application error metrics.

Latency

API Gateway response times, Lambda duration, ALB target response time.

Custom Metrics

Any CloudWatch alarm you've created — ConvOps handles it automatically.

Supported AWS Resources
🐳 ECS 🖥️ EC2 🗄️ RDS ⚡ Lambda ⚖️ ALB 🌐 API Gateway 🏎️ ElastiCache 📨 SQS 📦 DynamoDB 🪣 S3
Alert Channels

Choose one or both. Alerts land wherever your team already is — no new tools.

💬 WhatsApp # Slack
Alert Conditions
ALARM
ALARM state → Immediate notification

When a CloudWatch alarm transitions to ALARM, ConvOps ingests it instantly, runs AI analysis, and delivers a rich notification with root cause — not just a raw metric value.

OK
OK state → Resolved notification

When the alarm returns to OK, you receive a resolved message so you know the incident closed — no need to manually check CloudWatch.

DEDUP
Repeat-alert deduplication (flapping alarms)

If the same alarm fires repeatedly (flapping), ConvOps batches repeat notifications. You are only paged again after repeat_alert_threshold fires (default: 5). Each repeat message includes the total fire count and elapsed time. Configurable per workspace.

WATCHDOG
Persistent-alarm watchdog — re-notify even if no new fire

CloudWatch only sends SNS notifications on state transitions (OK→ALARM). If an alarm stays in ALARM without re-firing, no new SNS message is sent — meaning you'd never get a reminder. ConvOps runs a scheduled watchdog Lambda every 15 minutes that assumes your role, calls describe_alarms(StateValue='ALARM'), and pushes a repeat notification for any alarm still stuck in ALARM beyond the repeat_interval_minutes window (default: 15 min, configurable). The repeat message shows how long the alarm has been firing and how many times you've been notified.

02 Investigation Capabilities

Reply 4 to any alert to trigger a deep investigation. ConvOps pulls data from multiple AWS sources simultaneously, correlates everything, and delivers an AI root cause analysis — within seconds, without opening AWS console.

The first alert already includes AI analysis. Reply "4" when you want the full deep-dive with all data sources — metrics, logs, CloudTrail, cost, security groups, and more.
📊
CloudWatch Metrics
Last 30 min

Avg + max values for the relevant metric. Shows the trend leading up to the alarm threshold breach so you can see if it's a spike or a gradual increase.

📋
Application Logs
20 min before → 10 min after alarm

Scans CloudWatch Logs Insights filtered for: ERROR WARN Exception timeout OOM. Time window spans from 20 min before the alarm through 10 min after — captures both leading indicators and the blast radius.

🐳
ECS Service State
Live

Running / desired / pending task counts. Deployment status. Failed task details. Stopped task reasons + exit codes — the exact message that tells you why a container stopped.

🖥️
EC2 Instance State
Live

Instance state, instance type, CPU credit mode (for burstable T-series). Confirms whether the instance is running or in a degraded / impaired state.

🗄️
RDS Database Status
Live

DB status, engine version, connectivity analysis including security group rules and VPC subnet configuration. Identifies whether the database is reachable from your application layer.

🛡️
Security Group Audit
Live

Inbound rules check. Missing port detection — flags if a required port (e.g., 5432 for PostgreSQL, 3306 for MySQL, 6379 for Redis) is not open to expected sources.

🌐
API Gateway Diagnostics
Live

5xx and 4xx error rates. CORS configuration status. Stage info (deployment ID, throttling limits). Distinguishes client errors from server-side issues.

⚖️
ALB Target Health
Live

Per-target group breakdown: healthy / unhealthy / draining target counts. Identifies which backend instances have dropped out of rotation.

💰
Cost Analysis
Last 7 days

Per-service spend breakdown. Spend spike detection: flags any service with cost >20% above its 7-day rolling average. Useful for spotting runaway resources during incidents.

📜
CloudTrail
Last 5 changes (2h)

The last 5 changes to the affected resource in the past 2 hours. Shows who changed what — deploys, config changes, SG modifications, IAM updates. Correlates changes to incidents.

🐙
GitHub Deploys
Optional — requires GitHub PAT

Recent commits and deployments correlated to the incident window. Shows which deploy is closest to the alarm, who authored it, and the commit message. Store a GitHub PAT in Secrets Manager and provide the ARN during setup to enable this source.

🤖
Claude AI — Root Cause Analysis
Automatic

All collected data is fed to Claude AI, which produces 3–5 bullet root cause analysis + recommended actions. Correlates metrics, logs, config changes, and resource state into a single coherent diagnosis with suggested next steps.

03 Alert Flow

End-to-end: from CloudWatch alarm to resolved incident.

☁️ CloudWatch Alarm state change
→
⚡ EventBridge Auto-routes all alarms
→
📣 SNS Topic HTTPS delivery
→
🔌 Ingest + Dedup SQS FIFO queue
→
🤖 AI Filter RCA + enrich
→
💬 WhatsApp / Slack You receive alert
→
✅ Resolved Audit logged
Step-by-step
1
CloudWatch Alarm — Any alarm in your account transitions to ALARM or OK state.
2
EventBridge catches it automatically — The ConvOpsAlarmStateChanges EventBridge rule (deployed in your account) captures every alarm state change across your whole account and routes it to the ConvOps SNS topic. No per-alarm wiring needed.
3
ConvOps Ingest + Dedup — The SNS HTTPS subscription delivers to ConvOps. A dedup check fires (same alarm won't page you again until it's fired 5× by default). The event goes into an SQS FIFO queue for ordered processing.
4
Notification Sent — The AI filter enriches the alert and you receive a WhatsApp or Slack message with the alarm details and initial AI analysis.
5
You Reply — Reply 1 to take action, 4 to trigger full deep investigation (all 11 data sources + Claude RCA).
6
Confirmed Action — ConvOps proposes the action and waits for you to reply YES. Confirmation expires after 15 minutes. Every action is logged to the audit trail.
W
Watchdog (parallel, runs every 15 min) — CloudWatch only sends SNS notifications on state transitions. If an alarm stays stuck in ALARM without re-firing, you'd never get a reminder. The watchdog Lambda runs on a schedule, assumes your role, calls describe_alarms(StateValue='ALARM'), and re-notifies for any alarm still open beyond the repeat_interval_minutes window (default: 15 min). This means you keep getting nudged until the alarm resolves — regardless of whether you took action or not.
04 Customer Stack — What Gets Deployed

ConvOps deploys a single CloudFormation stack into your AWS account via app.convops.io. Here is exactly what it creates — no surprises, no hidden resources.

Fully automated. Sign up at app.convops.io, enter your AWS Account ID, and the portal generates a pre-filled CloudFormation URL. Click once to open in the AWS console — all parameters are pre-filled. No YAML editing.
Stack resources (4 total)
Resource Type What it does
ConvOpsAccessRole IAM Role Read-only access (+ write if EnableActions=true). Protected by unique ExternalId via STS.
ConvOpsAlertTopic SNS Topic Receives alarm events. Subscribed via HTTPS to the ConvOps ingest endpoint. CloudWatch + EventBridge are authorised to publish.
ConvOpsAlertTopicPolicy SNS Policy Allows CloudWatch and EventBridge to publish to the SNS topic.
ConvOpsAlarmStateChanges EventBridge Rule Always deployed. Catches every ALARM + OK state change across your entire account automatically. No per-alarm setup needed.

Parameter Required Description
CustomerExternalId Auto-filled Generated by the portal as CONVOPS-{your-account-id}. Pre-filled in the CFN URL. NoEcho: true — never visible in the console.
EnableActions Optional Default false. Set true to grant write permissions. Controls a second IAM policy that enables all remediation actions globally across your account.
GitHubTokenSecretArn Optional ARN of a Secrets Manager secret containing a GitHub PAT. Enables deploy correlation in investigations — shows which commit triggered the incident.
IAM Role: ConvOpsAccessRole
  • Trusted by: ConvOps AWS account 009001720832 — only ConvOps can assume this role.
  • ExternalId: Generated as CONVOPS-{accountId} by the portal. Pre-filled in the stack URL — the customer never handles it manually. Prevents confused-deputy attacks.

  • When EnableActions=true: A second inline policy is attached granting write actions across ECS, EC2, RDS, Lambda, EKS, SQS, CloudFront, EventBridge, DynamoDB, ElastiCache, and Elastic Beanstalk. No resource-level or tag-level restrictions — the permission applies to all resources in your account.

05 Security Model

ConvOps has cross-account access to your AWS environment. Here's exactly what that means — no vague claims.

No stored AWS credentials

ConvOps never stores your AWS credentials. Access works via STS AssumeRole — short-lived tokens with a 15-minute TTL. Tokens expire automatically.

ExternalId protection

Your IAM role requires a unique ExternalId (generated per customer, stored in Secrets Manager). Prevents confused-deputy attacks — nobody else can assume your role.

Read-only by default

The ReadOnlyAccess managed policy covers all reads. Write actions require your explicit confirmation for every individual action.

Phone binding

Only the person who received the alert on their registered number/Slack account can confirm actions. Confirmation expires after 15 minutes (DynamoDB TTL on pending actions).

Audit log — 90 days

Every investigation and action is logged: timestamp, resource ARN, who approved, outcome. Exportable on request. 90-day retention.

Minimal data storage

We store only operational metadata: alarm events, conversation state. Never raw application logs, log content, secrets, or business data.

🇪🇺
EU data residency

All ConvOps infrastructure runs in eu-central-1 (Frankfurt). Data does not leave the EU. GDPR compliant.

Revoke instantly

Delete the ConvOpsAccessRole from your AWS console. ConvOps loses all access immediately — no support ticket, no waiting period.

06 Actions Available

32 remediation actions across 11 AWS services. All are live and production-ready. Every action requires two-step confirmation (reply 1 → reply YES) and is logged in the audit trail with timestamp and approver.

Requires EnableActions=true in your CloudFormation stack. Free plan: 10 actions/month. Pro: unlimited. Actions are blocked entirely if EnableActions was not set during stack deployment — update the stack parameter to enable.
ECS — 8 actions
Restart service

Forces a new deployment — cycles all running tasks. Clears hung containers, OOM state, connection pool saturation.

Scale up (+1 task)

Increments desired count by 1. Absorbs traffic spikes without a full restart.

Scale down (−1 task)

Decrements desired count by 1. Useful for cost reduction or isolating a bad task.

Scale to count

Set desired task count to a specific number directly.

Rollback

Redeploys the previous task definition revision. Reverts a bad deploy without touching code.

Update task memory

Registers a new task definition with higher memory and redeploys. Fixes OOM without a code change.

Update task CPU

Registers a new task definition with higher CPU allocation and redeploys.

Drain task

Stops one running task — ECS automatically replaces it. Removes a bad instance without touching the service.

EC2 — 3 actions
Reboot instance

Soft reboot via AWS API (~60s downtime). Clears transient OS / kernel issues without data loss.

Stop + start instance

Stops then starts — migrates to a new physical host. Clears persistent hung state. ~2 min downtime.

Snapshot root volume

Creates an EBS snapshot of the root volume. Non-destructive — good to do before risky actions.

RDS / Aurora — 6 actions
Reboot RDS

Restarts the database engine. Clears connection pool saturation and transient DB failures.

Failover RDS

Triggers Multi-AZ failover to the standby replica. Useful when the primary is degraded.

Snapshot RDS

Creates a manual RDS snapshot. No downtime — safe to do before any intervention.

Failover Aurora cluster

Promotes an Aurora reader instance to primary.

Pause Aurora Serverless

Pauses an Aurora Serverless cluster — stops billing immediately.

Resume Aurora Serverless

Resumes a paused Aurora Serverless cluster.

Lambda — 4 actions
Throttle (emergency stop)

Sets reserved concurrency to 0 — immediately stops all invocations. Use for runaway functions.

Unthrottle

Removes the reserved concurrency limit, restoring normal invocations.

Update memory

Updates memory allocation. CPU scales proportionally with Lambda memory.

Rollback alias

Points a Lambda alias to a previous published version. Instant rollback without redeployment.

EKS — 3 actions
Restart deployment

Rolling restart via annotation — zero downtime. All pods replaced in a controlled rollout.

Rollback deployment

Rolls the Kubernetes deployment back to its previous revision.

Scale deployment

Set the deployment replica count to a specific number.

SQS, CloudFront, EventBridge, DynamoDB, ElastiCache, Elastic Beanstalk — 8 actions
SQS — Redrive DLQ

Moves all messages from the dead-letter queue back to the source queue for reprocessing.

CloudFront — Invalidate cache

Invalidates cached objects for specified paths across all edge locations.

EventBridge — Disable rule

Disables an EventBridge rule — emergency stop for runaway scheduled jobs or event-driven loops.

EventBridge — Enable rule

Re-enables a previously disabled EventBridge rule.

DynamoDB — Update capacity

Updates provisioned read/write capacity units on a DynamoDB table.

ElastiCache — Reboot node

Reboots a specific cache cluster node.

ElastiCache — Failover

Promotes a replica to primary in a Redis replication group.

Elastic Beanstalk — Restart app server

Restarts application server processes without replacing EC2 instances.

Elastic Beanstalk — Rollback

Deploys a previous application version to the environment.

Free plan action limit: 10 actions/month. When the limit is reached you'll see: "You've used all 10 free actions this month. Upgrade to Pro ($49/mo) for unlimited actions." Alerts and investigations continue to work normally.
07 Configurable Settings

Adjust ConvOps behaviour per workspace from the app dashboard.

repeat_alert_threshold
Repeat notification threshold (flapping alarms)

How many times the same alarm must re-fire before ConvOps sends a repeat notification. Default: 5. Applied to alarms that flap (oscillate between ALARM and OK or fire repeatedly). Set lower for critical alarms, higher for noisy ones. Configured per workspace.

repeat_interval_minutes
Persistent-alarm re-notify interval

How many minutes between watchdog repeat notifications for alarms that are stuck in ALARM without re-firing. Default: 15 min. If you don't acknowledge or resolve an alert, ConvOps will re-notify you every N minutes until the alarm goes OK. Each repeat message shows the total duration and fire count. Configured per workspace.

alert_channels
Alert channels

Choose WhatsApp, Slack, or both. Configured during setup at app.convops.io.
