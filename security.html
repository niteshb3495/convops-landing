Security at ConvOps

What we access, how credentials work, how to revoke us, and where data goes — written for security reviewers and CTOs.

IAM access model

By default ConvOps uses read-only AWS API calls to investigate alarms (CloudWatch metrics and alarms, logs, ECS/RDS/Lambda describe APIs). Optional Pro remediation adds explicit write actions — each requires a human confirmation in chat before execution.

Read-only actions (baseline)

Includes: cloudwatch:GetMetricData, DescribeAlarms, GetMetricStatistics, ListMetrics, log read APIs (FilterLogEvents, GetLogEvents, describe groups/streams), ec2:Describe*, ecs:Describe*, ecs:List*, rds:Describe*, lambda:Get*, lambda:ListFunctions.

Pro write actions (human-approved only)

These are issued only after an engineer confirms in WhatsApp or Slack. They are scoped in our published CloudFormation template:

  • ecs:UpdateService
  • ec2:RebootInstances
  • rds:RebootDBInstance
  • lambda:InvokeFunction

The customer CloudFormation template ships an IAM role (not long-lived users). Review the full JSON here:

cloudformation/convops-setup.yaml — your team can diff this in minutes.

{ "Read": [
  "cloudwatch:GetMetricData", "cloudwatch:DescribeAlarms",
  "cloudwatch:GetMetricStatistics", "cloudwatch:ListMetrics",
  "logs:FilterLogEvents", "logs:GetLogEvents",
  "logs:DescribeLogGroups", "logs:DescribeLogStreams",
  "ec2:DescribeInstances", "ec2:DescribeInstanceStatus",
  "ecs:DescribeTasks", "ecs:DescribeServices", "ecs:ListTasks", "ecs:ListServices",

How credentials work

ConvOps assumes IAM roles in your account via sts:AssumeRole — we do not ask for IAM users or static access keys. Your stack sets ExternalId to your RegistrationToken, which mitigates confused-deputy attacks. Our service obtains short STS sessions (typically up to 15 minutes for operational calls). We never see your access keys. You create and own the role; we only assume it when investigating or executing an approved action.

How to revoke access

Delete the IAM role from your AWS account. Done. ConvOps loses the ability to assume that role immediately. No ticket queue required.

Data retention & subprocessors

Operational records use a 90-day TTL on DynamoDB tables where applicable. Phone numbers are masked in logs; we retain routing identifiers only as needed for delivery. Data is not sold or used for ads.

Third-party processing is limited to: Anthropic Claude API (alarm and log context for triage and RCA — no marketing use), and WhatsApp / Slack APIs for message delivery only.
